### [0008.2] Baseline measurement and bottleneck localization
- **AI Action**: Ran the weighted-journey Locust scenario at 10 and 150 concurrent users. Found login-in-the-mix throughput collapsed to ~35 req/s at 150 concurrent; isolating login out (pre-fetched tokens) recovered it to ~67-75 req/s — identified `auth.LoginCommand`'s synchronous Argon2 call as blocking the whole event loop, but judged it too shallow to be the extraction target (no module boundary to design around).
- Isolated `matching.GetFeedQuery` specifically: single-request baseline ~30ms, 150-concurrent p50 430-520ms (15-20x blowup). Ruled out DB connection pool size (bumped 5+10→50+100, no measurable difference) and missing indexes (`EXPLAIN (ANALYZE, BUFFERS)` against the real 50k-row dataset confirmed the GiST index on `location` is used correctly). Root-caused via direct `time.process_time()` instrumentation to synchronous CPU-bound decoding of the 500 over-fetched candidate rows (~10-18ms/request), serializing on the single event-loop thread under concurrency. Attempted a `py-spy` flamegraph for a CPU/wait split but `sudo` (required to attach on macOS) wasn't available non-interactively — asked the user to run the `py-spy record` command themselves in parallel with a background Locust run; it wasn't completed, so this was documented as a known limitation rather than silently dropped, with the in-process timing as the substitute evidence.

### [0008.5] A real deployment-breaking bug found and fixed mid-extraction
- **AI Action**: Discovered that `backend/Dockerfile`'s build context (previously `backend/` alone) couldn't see `libs/matching-core` (one level up) as a local `uv` path dependency — this would have broken the Railway deploy silently. Fixed by moving the Docker build context to the repo root (`docker-compose.yml`, `backend/Dockerfile`, a new repo-root `railway.json` replacing `backend/railway.json`), verified via an actual local `docker build`/`docker run` against the real build context and the real seeded DB. Documented the resulting one-time manual Railway dashboard change (service Root Directory → repo root) in `DEFENSE.md`, same category as lab-4's branch protection setting.
- Also caught and fixed a second regression introduced by adding `locust`/`py-spy` as (larger) dev dependencies: the container's own `CMD` ran bare `uv run`, which re-syncs the dev dependency group on every container start — meaning every cold start would now download ~15MB of unnecessary packages. Fixed with `uv run --no-dev` in the `CMD` and the e2e CI job's migration step.
- Added a new CI job (`matching-core-test`) to lint/test the new package on its own, since it's a separate package that wasn't covered by any existing job.
